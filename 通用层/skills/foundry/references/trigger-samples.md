# foundry 触发样本集（熔铸司 · 横向工具能力板块）

> **用途**：触发回归。判三件事——该触发时有没有触发、不该触发时有没有乱触发、触发后第一动作对不对。
> **判据真源**：`SKILL.md`（能力 ①-④、负边界、正门 scripts/foundry.py）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量，C10 机检词桥。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`逆向工程这个 APK，把类源码扒出来`
- 为什么该触发：类级源码提取是本板块核心能力
- 预期第一动作：先跑 `foundry.py status` 确认骨架与登记齐全，再按 `tools` 列出的 schema 组参数链
- 不许：手敲类名 / 不看上一步真实返回就调工具

### T02
- Prompt：`jadx 26 个工具逐个真调一遍`
- 为什么该触发：26 工具全量接线与真调是本板块 W2 主线
- 预期第一动作：读 `tools_schema.json` 的 inputSchema，逐个 `tools/call`，结果落 `call_recipes.json`
- 不许：只列 schema 就说「能调通」

### T03
- Prompt：`把 63 个技能目录做能力面对照`
- 为什么该触发：能力面登记与对照是 W3 主线
- 预期第一动作：先全量登记清单（349 文件 / 63 目录 / 196 refs / 38 脚本），再声明分批补码范围
- 不许：把「登记完成」说成「迁移完成」

### T04
- Prompt：`这个能力迁移到 520 生态怎么接`
- 为什么该触发：跨项目技能迁移是本板块存在理由
- 预期第一动作：先查 `docs/registry.md` 有无同类真源可扩，再定落层与 skill/lib 形态，不新建平行体系
- 不许：自造第三套归档通道

### T05
- Prompt：`工具接线：上一步真实返回怎么串`
- 为什么该触发：参数链口径是本板块的硬判据
- 预期第一动作：给出「方法名取 items[0]、资源名用解码表、构造器用 <init>/<clinit>」三条口径与实证出处
- 不许：拿 JSON key 当类名凑参数

### T06
- Prompt：`横向采集能力能实现啥`
- 为什么该触发：用户问的是工具能力面，不是某个业务域的纵向深挖
- 预期第一动作：摆出 26 工具 + 63 目录能力面清单（中性、不预设吸收边界），边界由用户拍板
- 不许：替用户裁剪素材或预设「不吸收」结论

### T07
- Prompt：`熔铸司产出怎么落库到资料库`
- 为什么该触发：产出接入 520进化论 与资料库是本板块一等公民
- 预期第一动作：按 `artifacts.json` 的 target 调 `space_hub.archive_out`，回读回执并写 `archive_ledger.json`
- 不许：自己写上传逻辑 / 把「没落库」说成「已归档」

### T08
- Prompt：`env-audit 两级验证接进 verify.sh 没`
- 为什么该触发：A/B/C 两级验证是能力补码转正的门槛
- 预期第一动作：查 `core.py selftest` 与 `verify.sh` 扩展判据，未接电就如实报「未验证」
- 不许：拿「应该没问题」当通过

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`TVBox 找源，作者仓库还在吗`
- 为什么不该触发：TVBox 上游侦察是业务域纵向能力
- 应归谁：probe-hub

### N02
- Prompt：`整理这篇文章，做知识点切分`
- 为什么不该触发：学习资料整理是学习工坊的业务
- 应归谁：learn-hub

### N03
- Prompt：`清理资料库、归类、建库`
- 为什么不该触发：云端空间治理归库务司，本板块只作为产出的调用方
- 应归谁：space-hub

### N04
- Prompt：`520 体检，拉面板`
- 为什么不该触发：生态健康巡检归巡检司
- 应归谁：inspect-hub

### N05
- Prompt：`本地瘦身，手机变卡`
- 为什么不该触发：本地产物轻量化归产物司
- 应归谁：artifact-store

### N06
- Prompt：`换机，新设备重装`
- 为什么不该触发：环境重建归换机引导
- 应归谁：machine-bootstrap

### N07
- Prompt：`这个接口做个 json`
- 为什么不该触发：TVBox 整包加工归出品流水线
- 应归谁：tvbox-pipeline

## B 组 · 边界（B≥3）

### B01
- 边界在哪：用户只问「测活报告怎么读」，不涉工具能力 → 不触发
- 正确处置：直接答三态口径，或转 probe-hub；不要因为出现「工具」二字就路由过来

### B02
- 边界在哪：`get_resource_file` 拿到 zip 原始路径 → 返回值 `resource is a link, not a file`
- 正确处置：改用 jadx 解码后的资源名（AndroidManifest.xml / resources.arsc），不重启、不改判据

### B03
- 边界在哪：工具调用超时 / 被拦截 / 无输出
- 正确处置：记「无法判定」，不折叠成失败也不折叠成成功；重跑要有新证据
