## §2 机制：结构化登记 + ast 实证

### 2.1 登记载体（复用现成真源，不新造文件）

`verify/病号映射表.json` 病15 条目加结构化 `gate` 字段（该表本就是「病号→修法→归宿(闸化/注入/归档)」的机器可读投影，

```json

  "script": "能力层/tvbox/skills/probe-hub/scripts/shellcrack.py",
  "selftest": "--selftest",
  "anchor": "S233①",
  "evidence": "能力层/tvbox/skills/probe-hub/references/S234_jadx类名级壳侦察与写源分档.md §2/§3",
```

- **安全性**：`hooks/next_anchor.py:193-205`、`hooks/guard_cmd.py:208-212` 都用 `.get('diseases')` / `.get('guard_rules')` 遍历，加字段不影响；
  `verify/tests/` 无对 `diseases` 字段集合的断言。该表在 `verify/` 下，不进技能镜像（不触发 C5）。
- **纪律**：gate 只放坐标+指针（M2 引用不复制），证据全文在 S234 / 台账。

### 2.2 实证函数 `_gate_landed` / `_selftest_landed`（chk_landing.py）

判4 对每个 `hot` 病号取 `reg.get(病号).gate`，调 `_gate_landed(repo, gate)`：

1. `gate` 必须是 dict 且有 `script`（否则「非结构化/缺落点」）。
2. 落点脚本文件**真实存在**（相对 repo；不存在 → 登记未落地，仍 yellow）。
3. `_selftest_landed(src, anchor)` 用 **ast 结构化节点**实证脚本里真有 selftest：

| 检查 | 判据 | 防的是什么 |
|---|---|---|
| 函数定义 | `ast.FunctionDef/AsyncFunctionDef` 且名含 `selftest` 或 `test_` 前缀 | 注释 `# def selftest()`、docstring 字样**不产生节点**，天然不算落点 |
| 接电 | 有 `'--selftest'` 字符串常量（argv/argparse）**或** `selftest()` 调用出口（SystemExit/sys.exit/裸调用） | 只有定义、从没被调用的「挂空」脚本 |
| 非空壳 | 函数体去掉 `pass` 和 docstring 后还有语句 | `def selftest(): pass` 假闸 |
| 判据锚点 | `anchor`（病15=`S233①`）出现在 selftest 函数体的**字符串常量**里，跳过 docstring | 注释里的 `S233①` 不算；挂一个不相干脚本也不算 |

### 2.3 本轮同型坑：病15「识别范围≠对象范围」

- **历史镜像**：`verify/gate_scan.py:230-243` 的 `collect_impl` —— 首版正则只要求「出现 `# impl: B-xx Sn`」，
  把 docstring 里的示例行也当成落点（病15 第 6 例）；收严成「整行注释」后又是另一种窄识别。
- **本轮防御**：不用「扫 `--selftest` 字样」，而用 ast 节点类型判断。注释与 docstring 造不出 `FunctionDef`/`Call`，
  所以既不误收（注释/docstring）、又不漏判（五种真实后接写法全覆盖）：
  `① def selftest + raise SystemExit` / `② async def + sys.exit` / `③ 方法或 test_ 前缀` / `④ argparse --selftest 开关` / `⑤ 裸调用无 argv`。
- **单测覆盖**：`verify/gate_experience.py:_gate_selftest` 五种形态全 True、六类反例全 False（注释/docstring/无函数/空壳/未接电/锚点只在注释）。
